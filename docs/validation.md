# 현재 검증 결과

최신 변경 검증 환경은 macOS arm64, .NET SDK 10.0.401 / 런타임 10.0.12입니다. 아래 최초 CLI 성능 수치는 이전 Linux x64 환경에서 얻은 값입니다.

- 잠금파일을 사용하는 의존성 설치와 Release 빌드 성공. 경고·오류 0개.
- xUnit 통합·회귀 테스트: 133개 통과, 0개 실패, Windows·Linux 전용 검사 5개 건너뜀.
- 기존 보류·요청 시 탐색, 오류·취소 시 색인 보존, schema 1·2 읽기와 schema 3 이전 테스트 통과.
- 이름·전체 경로 다중 단어 리터럴 검색, 크기·날짜 필터, 모든 정렬 방향, 안정적 페이징, 정확한 전체 개수와 루트 상태를 검증했습니다.
- 이전 Linux 검증의 NuGet 취약성 검사에서는 사용한 소스 기준 알려진 취약 패키지가 없었습니다.
- Windows·Ubuntu CI에서 같은 잠금파일 복원·Release 빌드·테스트를 실행합니다.

## Regex·JSON 설정·스캔 진단 검증

- `full`/`partial`, 대소문자 기본값·명시 설정, 한글·숫자 패턴, 대안 패턴의 전체 일치, 줄바꿈 경계와 Regex 주석 처리.
- 모든 깊이의 폴더 이름만 가지치기하며 파일 이름은 그대로 유지. scoped/on-demand 요청의 제외 조상 우회 방지와 동일한 갱신 계획기 정책.
- 잘못된 Regex·JSON 필드·중복 필드·타입·enum·null·루트 밖 경로를 DB 생성 전에 거부.
- Regex 시간 초과 때 이미 staging에 저장한 항목까지 폐기하고 기존 검색 항목·pending을 유지. 실패 후 후속 탐색 가능.
- JSON 상대 경로를 설정 파일 위치 기준으로 해석. CLI 제외·보류 목록 추가, 수치 옵션 우선, 설정을 재사용한 on-demand 완료.
- 경로·정확한 이름·Regex·파일 패턴의 우선순위와 중복 없는 사유별·종류별 통계.
- 관찰한 반복 폴더 이름만 집계, 제외 폴더 내부 미열거, 경로·이름 한도와 생략 건수, 이름별 최대 3개 예시, 스캔 간 통계 초기화.

macOS의 `/var` 심볼릭 링크를 테스트 경로로 사용하지 않도록 `TMPDIR=/private/tmp`에서 테스트했습니다. Windows·Linux 전용 검사는 해당 플랫폼의 CI에서 별도로 실행해야 합니다.

Windows CI에서 기존 `TestWorkspace.WriteFile`이 혼합된 경로 구분자를 반환해 색인의 정규화된 경로와 문자열 비교가 실패하는 문제를 확인했습니다. 테스트 도우미도 `Path.GetFullPath`로 경로를 정규화하도록 수정했습니다.

## CLI 기능 검증

실제 실행 파일로 별도의 임시 데이터에서 탐색·검색·부분 갱신을 실행했습니다.

| 항목 | 관찰 결과 |
|---|---|
| 포함할 파일 | 20개 폴더에 1,200개 |
| 제외할 파일 | `Cache` 폴더에 500개 |
| 전체 탐색에서 관찰한 항목 | 포함 파일 1,200개 + 폴더 20개 + 제외 폴더 자체 1개 = 1,221개 |
| 하위 폴더 하나 갱신 | 파일 60개와 범위 폴더 자체, 총 61개 관찰 |
| 검색 | 한글 부분일치·페이지 조회, 제외 파일 미반환 확인 |
| 변경 반영 | 하위 폴더의 삭제·추가 반영 확인 |
| 원본 경로가 없을 때 | 기존 색인 검색 성공 |

전체 탐색은 프로세스 시작 시간을 포함해 약 0.788초였습니다. 작은 Linux 임시 데이터와 해당 실행 시점의 캐시 상태에서 얻은 기능 검증 수치이며, 실제 HDD·NTFS·SMB의 처리량이나 대용량 성능을 나타내지 않습니다.

## 보류와 요청 시 탐색 검증

보류 기능의 테스트는 명시 규칙의 사전 가지치기, 비용 이력과 예산, 기존 색인 보존, 취소·오류 복구, 조회 범위와 Unicode 경계, 구색인 이전을 포함합니다. `pending`이 있으면 검색 결과가 없어도 미확인 범위가 표시되며, 해당 범위의 기존 결과는 계속 조회됩니다.

별도 CLI 프로세스들을 사용한 임시 데이터 검증에서도 다음을 확인했습니다.

- `Archive`의 파일 100개는 보류하고 일반 파일 20개를 색인.
- `pending` 명령으로 저장된 범위와 사유 조회.
- `--on-demand` 요청은 보류 정책·작업 예산을 우회해 파일 100개를 색인하고, 제외한 캐시 파일 50개는 미탐색.
- 이후 프로세스에서 저장된 항목 수 이력을 활용해 `Archive`를 다시 보류.
- 원본 경로가 없을 때도 보류 목록과 기존 검색 결과 조회.
- 0·음수·NaN·Infinity 시간 예산 입력 거부.

예산은 OS 호출 사이에서 적용되며 진행 중인 SMB 요청을 강제로 중단하지 않습니다. 보류 기능을 기본 설정에서 자동으로 켜지는 것으로 검증한 것은 아니며, 정책을 명시적으로 지정해 실행했습니다.

## 실제 장비에서 남은 검증

Windows NTFS와 실제 공유 폴더에서 파일 수, 초기 탐색 시간, 부분 갱신 시간, 검색 지연, 색인 크기, 디스크 읽기·대기 시간, 네트워크 사용량을 측정해야 합니다. 다중 사용자 변경과 연결 단절, 권한 오류, 느린 SMB 호출 중 취소도 확인해야 합니다. 자동 변경 감지와 USN 저널은 현재 구현 범위에 포함하지 않았습니다.

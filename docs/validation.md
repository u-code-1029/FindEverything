# 현재 검증 결과

검증 환경은 Linux x64, .NET SDK 10.0.401 / 런타임 10.0.12입니다.

- 잠금파일을 사용하는 의존성 설치와 Release 빌드 성공. 경고·오류 0개.
- xUnit 통합·회귀 테스트: 89개 통과, 0개 실패, Windows 전용 검사 2개 건너뜀.
- NuGet 취약성 검사에서 현재 사용한 소스 기준 알려진 취약 패키지 없음.
- Windows·Ubuntu CI 정의는 추가했지만 원격 CI는 아직 실행하지 않았습니다.

## CLI 기능 검증

실제 실행 파일로 별도의 임시 데이터에서 탐색·검색·부분 갱신을 실행했습니다.

| 항목 | 관찰 결과 |
|---|---|
| 포함할 파일 | 20개 폴더에 1,200개 |
| 제외할 파일 | `Cache` 폴더에 500개 |
| 전체 탐색에서 관찰한 항목 | 포함 파일 1,200개 + 폴더 20개 + 제외 폴더 자체 1개 = 1,221개 |
| 하위 폴더 하나 갱신 | 파일 60개와 범위 폴더 자체, 총 61개 관찰 |
| 검색 | 한글 부분일치·페이지 조회, 제외 파일 미반환 확인 |
| 변경 반영 | 하위 폴더의 삭제·추가 반영 확인 |
| 원본 경로가 없을 때 | 기존 색인 검색 성공 |

전체 탐색은 프로세스 시작 시간을 포함해 약 0.788초였습니다. 작은 Linux 임시 데이터와 해당 실행 시점의 캐시 상태에서 얻은 기능 검증 수치이며, 실제 HDD·NTFS·SMB의 처리량이나 대용량 성능을 나타내지 않습니다.

## 보류와 요청 시 탐색 검증

보류 기능의 테스트는 명시 규칙의 사전 가지치기, 비용 이력과 예산, 기존 색인 보존, 취소·오류 복구, 조회 범위와 Unicode 경계, 구색인 이전을 포함합니다. `pending`이 있으면 검색 결과가 없어도 미확인 범위가 표시되며, 해당 범위의 기존 결과는 계속 조회됩니다.

별도 CLI 프로세스들을 사용한 임시 데이터 검증에서도 다음을 확인했습니다.

- `Archive`의 파일 100개는 보류하고 일반 파일 20개를 색인.
- `pending` 명령으로 저장된 범위와 사유 조회.
- `--on-demand` 요청은 보류 정책·작업 예산을 우회해 파일 100개를 색인하고, 제외한 캐시 파일 50개는 미탐색.
- 이후 프로세스에서 저장된 항목 수 이력을 활용해 `Archive`를 다시 보류.
- 원본 경로가 없을 때도 보류 목록과 기존 검색 결과 조회.
- 0·음수·NaN·Infinity 시간 예산 입력 거부.

예산은 OS 호출 사이에서 적용되며 진행 중인 SMB 요청을 강제로 중단하지 않습니다. 보류 기능을 기본 설정에서 자동으로 켜지는 것으로 검증한 것은 아니며, 정책을 명시적으로 지정해 실행했습니다.

## 실제 장비에서 남은 검증

Windows NTFS와 실제 공유 폴더에서 파일 수, 초기 탐색 시간, 부분 갱신 시간, 검색 지연, 색인 크기, 디스크 읽기·대기 시간, 네트워크 사용량을 측정해야 합니다. 다중 사용자 변경과 연결 단절, 권한 오류, 느린 SMB 호출 중 취소도 확인해야 합니다. 자동 변경 감지와 USN 저널은 현재 구현 범위에 포함하지 않았습니다.
